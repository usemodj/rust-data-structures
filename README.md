# Rust 자료구조 노트

Rust의 자료구조와 알고리즘을 한국어로 학습하는 Axum 웹사이트입니다. 각 문서에는 개념, 복잡도, 실행 가능한 예제와 테스트, 참고자료가 들어 있습니다.

## 실행하기

Rust와 Cargo가 필요합니다. 프로젝트 폴더에서 다음을 실행하세요.

```powershell
cargo run
```

설정이 없으면 브라우저에서 <http://127.0.0.1:3000>을 엽니다. 기본 서버는 로컬 컴퓨터에서만 접근할 수 있습니다. 시작할 때 `dotenvy::dotenv()`가 현재 작업 디렉터리부터 상위 디렉터리까지 `.env`를 찾아 변수들을 프로세스 환경에 로드하고, 그중 `BIND_ADDRESS`와 `PORT`로 서버 주소를 정합니다. 예를 들어 다음처럼 설정할 수 있습니다.

```dotenv
BIND_ADDRESS=127.0.0.1
PORT=3000
```

새 설정 파일이 필요할 때는 `.env.example`을 참고하거나, 기존 `.env`가 없는 경우에만 다음 명령으로 복사하세요.

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
} else {
    Write-Output "기존 .env가 있어 복사하지 않았습니다."
}
```

예시 파일은 로컬 전용 설정이며 기존 `.env`를 덮어쓰지 않습니다. 프로세스 환경 변수는 `.env`보다 우선하고, 둘 다 없으면 로컬 주소 `127.0.0.1`과 포트 `3000`을 사용합니다. `.env`는 UTF-8로 작성하며 [`dotenvy`](https://docs.rs/dotenvy/0.15.7/dotenvy/)로 읽습니다. 주석, 따옴표 및 변수 치환 등의 문법은 `dotenvy`를 따릅니다. 기존 프로세스 환경 변수가 없으면 `.env`의 변수들이 프로세스 환경에 추가됩니다. 서버 주소는 그중 `BIND_ADDRESS`와 `PORT`를 사용합니다. 같은 키가 여러 번 있으면 첫 값을 사용합니다. 잘못된 설정이나 파일 읽기 오류가 있으면 서버를 시작하지 않습니다. `.env`는 Git에서 제외됩니다. 종료하려면 `Ctrl+C`를 누릅니다.

### 같은 네트워크의 스마트폰에서 접속하기

신뢰할 수 있는 네트워크에서만 다음 설정으로 서버를 실행합니다. `BIND_ADDRESS`는 수신할 IP 주소이며, `0.0.0.0`은 모든 IPv4 인터페이스에서 수신한다는 뜻입니다. `PORT`는 사용하지 않는 포트를 선택합니다.

```powershell
$env:BIND_ADDRESS = "0.0.0.0"
$env:PORT = "3001"
cargo run --offline
```

PC의 Wi-Fi IPv4 주소를 `ipconfig`로 확인하고, 같은 Wi-Fi의 스마트폰 브라우저에서 `http://PC의-IPv4-주소:3001`로 접속합니다. `0.0.0.0` 자체는 접속 주소가 아닙니다. 특정 인터페이스에서만 수신하려면 `BIND_ADDRESS`에 해당 PC의 IPv4 주소를 지정할 수도 있습니다. PC의 주소가 변경되면 접속 주소도 달라집니다.

이 서버는 인증과 HTTPS가 없으므로 네트워크의 다른 기기가 읽을 수 있습니다. 공용·신뢰할 수 없는 네트워크에서는 사용하지 말고 라우터 포트 포워딩으로 인터넷에 공개하지 마세요. Windows 방화벽이 외부 연결을 차단할 수 있으며, 필요한 경우 관리자에게 해당 TCP 포트와 신뢰할 수 있는 로컬 네트워크로 제한된 허용 규칙을 요청하세요. 방화벽을 전체 해제하지 마세요. 스마트폰과 PC가 같은 Wi-Fi에 있어도 게스트망의 기기 간 격리나 VPN 때문에 연결이 안 될 수 있습니다.

설정을 적용한 PowerShell 창에서는 환경 변수가 유지됩니다. 다시 로컬 전용으로 실행하려면 `$env:BIND_ADDRESS = "127.0.0.1"`로 지정하거나 `.env`의 `BIND_ADDRESS`를 로컬 주소로 변경한 뒤 환경 변수 설정을 지우고 서버를 다시 시작하세요. 환경 변수를 지우면 `.env` 값이 다시 적용되므로 `.env`가 `0.0.0.0`이라면 계속 네트워크에 노출됩니다.

## 테스트

```powershell
cargo test
```

서버와 렌더러의 단위 테스트를 실행합니다. 각 Markdown 파일의 모든 Rust 코드 블록을 임시 파일로 추출하여 일반 프로그램과 테스트 프로그램으로 각각 컴파일하고 실행합니다. 따라서 `rustc`와 플랫폼의 Rust 링크 도구가 필요합니다.

테마와 문서 사이드바 선택 및 브라우저 저장 동작의 JavaScript 테스트는 Node.js가 설치되어 있다면 별도로 실행할 수 있습니다.

```powershell
node --test tests/theme.test.cjs tests/sidebar.test.cjs
```

상단의 테마 선택 메뉴에서 밝은, 어두운, 따뜻한 테마를 고를 수 있습니다. 문서 페이지의 `메뉴 접기` 버튼으로 사이드바를 접거나 펼칠 수 있습니다. 두 선택은 브라우저 저장소에 보관되며 저장소를 사용할 수 없는 환경에서는 현재 페이지만 적용됩니다. JavaScript가 꺼져 있으면 사이드바는 항상 표시됩니다.

## 문서 편집

원본은 `docs/`에 주제별 Markdown으로 저장되어 있습니다. 문서는 컴파일 시 실행 파일에 포함되므로 수정 후 서버를 다시 빌드하고 실행해야 반영됩니다. 새 문서를 추가할 때는 `src/main.rs`의 `DOCUMENTS` 목록에도 등록하세요.

이 사이트는 자체 간단한 Markdown 렌더러를 사용합니다. 제목(`#{1..4}`), 문단, `-` 목록, 코드 펜스, 인라인 코드, 굵은 글씨(`**...**`), 표와 HTTP(S) 링크를 지원합니다. 표는 헤더와 세 개 이상의 하이픈으로 된 구분 행이 필요하고, 셀 안의 `|`는 `\|`로 이스케이프할 수 있습니다. 이미지 문법은 `src/diagrams.rs`에 등록된 번들 다이어그램만 표시하며 외부 이미지는 지원하지 않습니다. 중첩 목록 등 전체 Markdown 문법은 지원하지 않으며 HTML은 이스케이프됩니다. 외부 폰트를 불러올 수 없을 때는 시스템 글꼴을 사용합니다.

----

1. GitHub 저장소 만들기
GitHub 새 저장소 만들기에서 저장소 이름을 입력하고 공개 여부를 선택하세요. README, .gitignore, 라이선스는 추가하지 않고 빈 저장소로 만듭니다. 프로젝트에 이미 해당 파일들이 있습니다.

2. 프로젝트에서 Git 초기화

```sh
git init -b main
git add .
git status
git diff --cached
```

3. 커밋하고 GitHub에 올리기
아래 주소에서 사용자이름과 저장소이름을 실제 값으로 바꾸세요.

```sh
git commit -m "Initial commit"
git remote add origin https://github.com/사용자이름/저장소이름.git
git push -u origin main
```

이후 변경 사항을 올릴 때는 다음을 실행하면 됩니다.

```sh
git add .
git status
git diff --cached
git commit -m "변경 내용"
git push
```
